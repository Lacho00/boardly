# Boardly Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Boardly the "instrument panel" identity (dark and light themes, dense home page, severity-first) on all five pages, with no change to features, checks or schema.

**Architecture:** Design tokens are CSS custom properties in `globals.css`, exposed to Tailwind 4 via `@theme inline`, so components use utilities such as `bg-panel`, `text-dim`, `border-line`. Theme is chosen by a cookie read in the root layout (`data-theme` on `<html>`), falling back to `prefers-color-scheme`. Home data is shaped by pure, tested helpers in `src/lib` (severity, uptime buckets, sparkline points, summary); components only render. Rings, strips and sparklines are CSS and inline SVG.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind 4, Prisma 5 + SQLite, Vitest + Testing Library (jsdom), `next/font/google`.

**Spec:** `docs/superpowers/specs/2026-10-17-redesign-design.md`. Visual reference: `docs/superpowers/specs/assets/redesign-mockup-v4.html` (open in a browser, `tema` button toggles theme).

## Global Constraints

- No new runtime or dev dependency. No chart library. Icons are inline SVG.
- No schema change. The only data change is `prisma/seed.mjs`.
- Token values start from the spec table (bg `#0e0d0b`/`#f6f3ec`, panel `#161512`/`#fffdf8`, line `#2a2823`/`#ddd6c6`, ink `#ece8dd`/`#1c1a15`, dim `#8a8578`/`#7a7466`, ok `#7cffb2`/`#0f9d58`, warn `#ffb020`/`#b86e00`, crit `#ff5a4f`/`#d6372b`), adjusted only as far as WCAG AA (4.5:1 for text) requires; before and after values go in the block 1 PR description.
- Fonts: JetBrains Mono (data, labels, body UI), Space Grotesk 500/700 (names, headings, large figures), via `next/font/google`, replacing Geist. Micro-labels 10px uppercase wide tracking, metric values 16px, summary figures 27px.
- Status colours: green = OK and brand, amber = warning, coral = critical. Colour is never the only signal (tag text and numbers accompany it).
- Site severity = worse of latest `HealthCheck` status and SSL tone (`ssl` under 7 days critical, under 30 warning; invalid certificate critical). Health status `error` and `critical` map to critical. Scores, LCP and response time colour their own figures only. Existing `scores.ts` thresholds do not change.
- Uptime counts a check as down only when `status === 'error'`.
- Nav alert count keeps `getCriticalAlertCount` (critical among the 50 latest alerts).
- Home sorts critical, warning, healthy, unknown, then name. Compact row above 8 sites (`COMPACT_AFTER = 8`).
- UI copy stays English. No emoji in the UI. No client names anywhere (demo data stays Acme, Northwind, Globex, Initech).
- Touch targets at least 24x24 on mobile; `prefers-reduced-motion` stops the live-dot pulse; visible focus ring.
- `DEMO_MODE=1` behaviour, links, forms, PDF and report endpoints unchanged.
- Process: each block is a branch off `dev` (`design/redesign-1-foundation` ... `-4-secondary`), a PR into `dev`, English commit messages, no attribution lines. Before each PR run `npm run lint`, `npm test`, `npm run build`, and review the diff with the `ocr-review` skill (not the generic reviewers). The spec branch `docs/redesign-spec` is merged into `dev` first.
- Verification rule: every change of tag or classes is measured before and after in the real browser (`getComputedStyle`: color, backgroundColor, fontSize, fontFamily, borderWidth, borderRadius; `getBoundingClientRect`: width, height), desktop and mobile, both themes, across every element sharing the class. Use the installed Chromium (`/usr/bin/chromium` via the existing Playwright MCP); never install browsers.

## Review Focus

- Site with no health checks yet (just added): severity `unknown`, strip all `none`, uptime shown as `-`, never `NaN%`.
- Latest SSL check invalid or `daysRemaining` null: invalid is critical, null days with a valid cert gives no SSL signal.
- Zero sites: home shows the empty state, summary helpers return nulls, no division by zero or `Math.max()` of an empty list.
- Theme cookie with a garbage value: falls back to the system preference, never throws.
- Very long site names and URLs: truncate with ellipsis in rows (desktop and 360px mobile), no horizontal page scroll.
